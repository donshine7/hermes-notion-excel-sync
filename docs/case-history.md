# 사건 히스토리 운영 계약

`사건 히스토리`는 사건별 실제 업무 사건을 시간순으로 조회하기 위한 Notion DB입니다.
기존 `변경이력`은 승인된 Notion 속성 변경의 시스템 감사 기록이므로 그대로 유지합니다.

## 데이터 경계

- Excel만 사건 사실의 권위 있는 입력입니다.
- 이메일과 Wiki는 요약·분류를 돕는 보조 근거이며 Excel 사실을 덮어쓰지 않습니다.
- 원본 Excel과 원본 폴더는 항상 읽기 전용입니다.
- 사건 히스토리 생성·수정도 다른 Notion 변경과 동일하게 정확한 Telegram 승인이
  필요합니다.
- 승인된 사용자 수정은 Notion과 Wiki 승인 오버레이에 함께 기록합니다.

## 이벤트 생성 규칙

한 Excel 원본 행과 한 사건번호의 조합은 최대 한 개의 주 이벤트를 만듭니다. 명시된
발생일 후보가 여러 개면 가장 최근 날짜를 선택하며, 같은 날짜에서는 등록결정, 업무완료,
연락, 출원, 업무접수, 업무시작 순으로 구체적인 유형을 우선합니다.

발생일 후보:

- 등록결정일
- 완료일·종료일·처리일
- 연락일
- 출원일
- 접수일·받은날짜·수신일
- 의뢰일·착수일·시작일

법정기일·등록마감일·회신기한·내부기일은 발생일로 쓰지 않고 `다음기한`에만 기록합니다.
발생일을 읽을 수 없으면 현재 시각이나 파일 수정 시각으로 대체하지 않습니다. 날짜가
없는 행은 이벤트를 만들지 않으며, 잘못된 날짜는 사람 검토 대상으로만 보냅니다.

## 중복과 정정

`이벤트ID`는 사건번호, 안정적인 Excel 원본 행 키, 이벤트 슬롯으로 계산합니다. 날짜,
요약 또는 상태가 정정되어도 ID는 유지되므로 기존 페이지를 갱신하고 중복 페이지를 만들지
않습니다. `source:sha256:...` 같은 내부 키는 사건번호로 사용하지 않습니다.

## Notion 속성

| 속성 | 형식 | 의미 |
|---|---|---|
| 히스토리명 | title | `사건번호 · 발생일 · 이벤트유형` |
| 이벤트ID | rich_text | 중복 방지용 안정 식별값 |
| 사건번호 | rich_text | 사람이 검색할 사건번호 |
| 발생일 | date | 원본에 명시된 실제 사건일 |
| 수집일시 | date | 해당 로컬 스냅샷을 읽은 시각 |
| 이벤트유형 | select | 등록결정, 업무완료, 연락, 출원, 업무접수, 업무시작 |
| 요약·상세내용 | rich_text | 원본 필드의 결정론적 요약 |
| 다음조치·다음기한 | rich_text/date | 명시된 후속 작업과 기한 |
| 출처유형·출처위치 | select/rich_text | Excel 및 시트·행 |
| 원본버전·원본해시 | rich_text | 승인 재검증용 출처 정보 |
| 신뢰도 | number | 분석 신뢰도 |
| 검토상태·사람확인 | select/checkbox | 승인 후에만 기록되는 확인 상태 |
| 사건 | relation | `한국 특허 사건` DB 관계 |

Notion에서 기본 보기는 `발생일` 오름차순, 최신 보기에는 `발생일` 내림차순 정렬을
권장합니다. Notion API의 스키마 생성은 보기 구성을 만들지 않으므로 정렬 보기는 한 번
수동으로 설정합니다.

## 안전한 최초 생성

다음 Telegram 명령은 GET-only 사전검사와 고정 스키마 제안만 만듭니다.

```text
/nx_schema_plan case-history <NOTION_PARENT_PAGE_ID>
```

표시된 전체 속성·관계·digest를 검토한 뒤 정확한 `/nx_schema_approve`를 별도 메시지로
보내야 DB가 생성됩니다. 생성 승인과 데이터 동기화 승인은 서로 재사용되지 않습니다.
